# Bounded Repair Loop

## Choose Repairs

Sort failed criteria by visual impact:

1. silhouette;
2. primary proportions and spacing;
3. landmarks and attachments;
4. form continuity;
5. surface treatment;
6. presentation-only issues.

Repair the smallest set of named forms that can improve the weakest score. Avoid broad rebuilding when a measured transform or focused edit is sufficient.

## Execute A Pass

1. Confirm `resolved_target_objects` is non-empty and current.
2. Choose one cohesive trusted repair script for cross-object or broad form changes; choose an exact helper only for an isolated requested edit.
3. Fetch the selected execution schema and apply one coherent repair batch.
4. Refresh object names after creation, deletion, join, separation, or rename.
5. Recapture the same reference-aligned and diagnostic views.
6. Rescore every affected criterion.
7. Continue only while a concrete below-floor finding remains and the pass limit is not exhausted.

Do not rely on current selection as the target contract.

## Repair Execution

With active trust, default to one cohesive repair script built from the brief's named forms, measurements, failed criteria, and constraints. Do not embed a reusable category base or subject-specific template. Read Blender version and RNA enum state before version-sensitive assignments. Verify script execution and refresh targets afterward.

Use a bounded helper instead when the user explicitly requests helpers, trust is off, or one exact operation is intentionally isolated. A script failure should first trigger traceback-guided repair from the checkpoint, not an automatic downgrade to primitive-only construction.

Evidence capture, inspection renders, final render jobs, and preview decisions remain helper operations after the scripted repair. Their presence in the request does not change the repair execution strategy.

## Stop Conditions

Stop repairing when:

- all applicable criteria meet the quality floor; or
- the planner's maximum repair passes are exhausted; or
- missing reference evidence or an unsupported operation blocks a valid comparison.

When blocked, report the failed criterion, current score, evidence, attempted repairs, and exact missing capability. Do not relabel an incomplete result as complete.

Leave successful or blocked changes in pending preview until the user explicitly chooses commit or revert.

Passing the gates changes status to `ready_for_user_review`; it does not authorize commit, revert, save, or further unsupported polish.
